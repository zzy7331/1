# 第一阶段开发说明

## 已完成能力

- 读取已发布模板并校验模板版本定义；官方 seed 提供“通用商品上新套装”。
- 中文三步创建向导：商品信息、三个营销卖点与视觉方向。
- 通过事务创建项目，保存不可变模板快照、项目变量、商品来源资产和五个画板。
- 项目工作区按持久化坐标展示五块画板，当前为只读状态，并显示中文占位和错误信息。
- `e2e/create-project.spec.ts` 覆盖模板中心到新建五画板工作区的浏览器旅程。

## 明确排除

本阶段不包括下列能力：

- 真实上传和对象存储
- 图像质量分析
- AI 任务或候选结果
- Konva 编辑
- 变量与图层的联动
- 版本恢复
- 导出
- 计费
- 品牌中心
- 团队审核

因此，五个画板显示“等待 AI 生成”是只读占位，不能视为素材已经生成。

## 开发数据库重置

优先重建专用开发数据库，以避免误删共享数据。例如先删除并重新创建本机 `ai_canvas`，再执行：

```bash
pnpm db:generate
pnpm prisma migrate deploy
pnpm db:seed
```

也可对**专用开发数据库**执行：

```bash
pnpm prisma migrate reset
```

> 警告：上述重置方式都会删除目标数据库中的数据。绝不能对生产数据库运行 `prisma migrate reset`、删除数据库或使用测试数据库连接串。

## 下一阶段边界

后续工作应拆成两个独立计划，避免混入本阶段：

1. **AI job orchestration**：定义任务队列、状态机、候选产物存储与失败重试边界。
2. **Editable Konva canvas**：定义画板编辑交互、图层模型、变量绑定、保存与版本语义。

两个计划都以前一阶段已经持久化的项目、模板快照和画板为输入；它们不改变第一阶段的模板创建契约。

## 已知环境限制

- 本地数据库必须是 PostgreSQL 16，且 Prisma 迁移和官方 seed 已执行；没有模板数据时，模板中心和 E2E 旅程无法完成。
- E2E 必须使用独立测试数据库。它创建新项目，但不清理或修改不可变模板版本。
- 包管理器会在依赖状态不匹配时尝试清理 `node_modules`。在无交互终端中，这可能被 `ERR_PNPM_ABORTED_REMOVE_MODULES_DIR_NO_TTY` 阻止；应在可交互环境使用项目锁定的 pnpm 10.32.1 完成 `pnpm install`，而不是绕过保护或改用 SQLite。

## 验证矩阵

| 项目 | 命令或前置条件 | 预期覆盖 |
| --- | --- | --- |
| 静态检查 | `pnpm lint`、`pnpm typecheck` | ESLint 与 TypeScript |
| 单元测试 | `pnpm test` | 表单校验、向导及只读工作区 |
| 集成测试 | `pnpm test:integration`，迁移和 seed 已完成 | 项目事务、快照、变量、资产和五画板 |
| 浏览器验收 | `pnpm test:e2e`，独立测试数据库、迁移和 seed 已完成 | 模板 → 向导 → API → 新项目五画板 |
| 生产构建 | `pnpm build` | Next.js 生产构建 |
